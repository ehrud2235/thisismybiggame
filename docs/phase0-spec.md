# Phase 0 기획 상세 — 서서 주먹만

> 담당: 기획 AI · 대상: 개발 AI
> 관련 문서: [concept.md](concept.md)

## 0. 이 문서가 답해야 할 질문은 하나

**주먹 궤도를 내가 만들고, 상대 몸을 읽어서 막는 싸움이 두 사람을 10판 이상 붙잡아 두는가?**

킥, 태클, 클린치, 그라운드, 온라인은 전부 없다. 주먹 하나로 재미가 안 나오면 나머지를 붙여도 재미가 안 난다.

아래 수치는 전부 **시작값**이다. [§11](#11-실시간-조정-가능해야-하는-값)의 값은 게임을 끄지 않고 바꿀 수 있어야 한다.

## 1. 범위

| 만든다 | 만들지 않는다 |
|---|---|
| 선수 2명 (같은 체급, 같은 능력치, 둘 다 오서독스) | 킥, 니킥, 엘보 |
| 로컬 2인 (패드 2개, 한 화면) | 태클, 클린치, 그라운드 |
| 궤도 입력 주먹 (양손) | 온라인 |
| 몸으로 막는 가드, 가드 위치 조절 | AI 상대 |
| 상체 움직임 (슬립, 롤, 젖히기) | 선수 선택, 커스터마이즈 |
| 스텝 (아날로그) | 메뉴, 타이틀 화면 |
| 페인트, 커밋 전 궤도 전환 | 사우스포, 스탠스 스위치 |
| 균형, 스태미나, 머리/몸 데미지 | 체력바, 스태미나바 (디버그 제외) |
| 흔들림, 다운, KO, TKO | 판정 심사 연출 |
| 1라운드 3분 | 케이지, 로프 |

## 2. 경기장과 카메라

- **원형 매트, 지름 9m.** 옥타곤과 비슷한 크기다. 경계는 보이지 않는 부드러운 벽이다
- **카메라: 방송 중계식 측면.** 두 선수를 잇는 선에 수직으로 본다. 두 선수가 가까우면 줌인, 멀면 줌아웃
- 카메라는 천천히 따라간다. 흔들림은 KO급 타격에서만 아주 약하게 준다

## 3. 조작 (게임패드)

| 입력 | 동작 |
|---|---|
| 왼쪽 스틱 | **스텝.** 아날로그, 연속. 항상 상대를 향한다 |
| **RB** | **앞손 (왼손)** |
| **RT** | **뒷손 (오른손).** 누르는 깊이만큼 체중이 실린다 |
| 오른쪽 스틱 | **상황에 따라 세 가지** (아래 표) |
| LB (누르는 동안) | 가드 조이기 + 가드 위치 조절 모드 |
| LT (누르는 깊이) | 자세 높이. 낮으면 바디를 친다 |
| X + 손 버튼 | 페인트 |

### 오른쪽 스틱은 상황에 따라 역할이 바뀐다

| 상황 | 오른쪽 스틱의 역할 |
|---|---|
| 손 버튼을 누른 순간과 출발 단계 | **궤도** |
| LB를 누르고 있는 동안 | **가드 위치** |
| 그 외 | **상체 움직임** |

이렇게 하면 버튼을 늘리지 않고도 궤도, 가드, 상체를 모두 아날로그로 다룰 수 있다.

## 4. 주먹

### 4.1 버튼을 누르는 순간 출발한다

**입력 지연은 0이다.** 궤도를 다 그린 다음에 나가는 방식이 아니다. 누르는 순간 주먹이 출발하고, 그 순간의 오른쪽 스틱 방향이 궤도를 정한다. 출발 단계 동안 스틱을 움직이면 궤도가 더 휜다.

템포는 여기서 나온다. 머릿속에서 "지금"이라고 생각한 순간 주먹이 나가야 한다.

### 4.2 스틱 방향이 곧 궤도다

뒷손(오른손) 기준. 앞손은 좌우가 반대다.

```
                  위
             (오버핸드)
                  │
   안쪽 ──── 중립(스트레이트) ──── 바깥쪽
  (각진 스트레이트)  │        (훅)
                  │
                 아래
              (어퍼컷)
```

- **방향 = 주먹이 들어오는 각도.** 바깥이면 옆에서, 아래면 밑에서, 위면 위에서 들어온다
- **기울기 크기 = 휘는 정도.** 조금 기울이면 숏 훅, 끝까지 기울이면 루핑 훅이다
- **대각선 = 사이 궤도.** 아래-바깥은 쇼벨 훅, 위-바깥은 루핑 오버핸드
- **시스템은 주먹 종류를 분류하지 않는다.** 360도 방향과 기울기의 모든 조합이 각자 다른 궤도다
- 로그와 디버그 표시용 이름만 붙인다(가장 가까운 기본형)

### 4.3 목표는 자동, 궤도는 수동

- **목표 지점은 자동이다.** 버튼을 누른 순간 상대 머리(LT로 낮춘 상태면 몸통)의 위치를 노린다
- **출발 단계 동안만 목표를 약하게 따라간다.** 커밋 이후에는 따라가지 않는다
  - 왜: 주먹이 머리를 끝까지 따라가면 슬립이 소용없어진다. **주먹은 머리가 있던 곳으로 간다.** 그래서 슬립과 롤이 통한다
- **사거리 끝에서는 약간 늘어난다**(팔 길이의 약 10%)
  - 왜: 대충 휘둘러도 그럴듯하게 맞아야 첫 30초가 재밌다. 정확한 조준은 실력이 아니라 조작 부담이다. 실력은 **언제, 어떤 궤도로** 치느냐에 있다

### 4.4 속도

실제 주먹 속도를 기준으로 잡는다. **주먹을 보고 막을 수는 없다.** 사람의 시각 반응 속도는 0.2~0.25초다.

| 기본형 | 출발 → 타격 (체중 0) | 체중 최대 |
|---|---|---|
| 잽 (앞손 스트레이트) | 0.16초 | — |
| 뒷손 스트레이트 | 0.20초 | 0.30초 |
| 훅 | 0.22초 | 0.34초 |
| 어퍼 | 0.22초 | 0.32초 |
| 오버핸드 | 0.28초 | 0.40초 |

- 사이 궤도의 시간은 **경로 길이에 비례**한다. 크게 휠수록 오래 걸린다
- **체중 최대일 때 늘어나는 시간은 대부분 준비 동작이다.** 어깨가 뒤로 빠지고, 뒷무릎이 굽고, 골반이 돈다. 이게 상대가 읽는 신호다
- **앞손의 힘은 스텝에서 나온다.** 앞으로 스텝하면서 친 잽은 체중이 실린다
- **준비 동작 없이 얻는 체중은 최대 60%다.** 전진 스텝, 슬립한 쪽 손, 흐름 연결로 얻는 체중을 다 합쳐도 60%를 넘지 않는다. **100%는 준비 동작을 보여줄 때만** 나온다. "센 주먹은 읽힌다"는 원칙을 지키기 위한 상한이다

### 4.5 커밋 지점과 페인트

- **커밋 지점: 출발 후 35%.** 이 전에는 멈추거나 궤도를 바꿀 수 있고, 이 뒤에는 끝까지 나간다
- **페인트: X를 누른 채 손 버튼을 누른다.** 어깨와 골반은 진짜 공격과 똑같이 움직였다가 궤도의 30% 지점에서 돌아온다
  - 처음에는 "커밋 전에 버튼을 떼면 페인트"로 설계했지만, 잽의 커밋 지점이 0.056초라서 사람이 그보다 빨리 버튼을 뗄 수 없다. 구현 단계에서 수식 버튼으로 바꿨다 ([§16](#16-구현하면서-바뀐-것))
- **커밋 전 궤도 전환:** 출발 단계에서 스틱 방향을 바꾸면 궤도가 바뀐다. LT를 누르면 바디로 떨어진다
  - 예: 잽으로 출발 → LT → 바디 잽 / 훅으로 출발 → 스틱 위로 → 오버핸드

### 4.6 흐름: 이전 주먹의 복귀가 다음 주먹의 준비다

콤보 목록 없이 실제 콤비네이션이 자연스럽게 빨라지게 만드는 규칙이다.

- 주먹을 칠 때마다 몸통이 한쪽으로 돈다. 뒷손은 앞쪽으로, 훅은 반대쪽으로
- **다음 주먹이 몸통을 반대 방향으로 돌리면 "흐름 연결"이다.** 출발 시간 −30%, 체중 보너스
  - 잽 → 스트레이트, 스트레이트 → 앞손 훅, 앞손 훅 → 스트레이트. 실제 복싱의 기본 콤비가 전부 여기에 해당한다
- **같은 방향으로 또 돌리면 연결이 끊긴다.** 출발 시간 +20%
- **복귀 중에도 다음 주먹을 칠 수 있다.** 모션이 끝나기를 기다리지 않는다

### 4.7 헛치면

- 체중을 실은 만큼 **앞으로 쏠린다.** 체중 최대 헛침은 0.35초 동안 쏠린다
- 쏠린 동안: 뒤로 스텝하는 속도 −50%, 맞으면 균형 붕괴가 크다
- **조작은 끊지 않는다.** 불리해질 뿐이다

## 5. 방어

### 5.1 가드는 실제 물체다

- 양손과 팔뚝은 충돌하는 물체다. 기본 위치는 턱 앞
- **주먹이 가드에 부딪히면 막힌다.** 가드 사이나 옆으로 들어오면 맞는다
- **칠 때는 그 손이 가드에서 빠진다.** 뒷손을 치면 오른쪽 얼굴이 빈다. 실제와 같다
- 막힌 타격: 데미지 15%, 가드가 흔들려서 0.2초 동안 복귀가 늦어진다
- 체중을 실은 타격은 가드째로 밀어서 머리에 약간의 데미지를 준다

### 5.2 가드 조이기와 위치 (LB + 오른쪽 스틱)

- LB를 누르면 **가드를 조인다.** 막는 면적이 늘고, 막힌 타격의 데미지가 5%로 줄어든다
- 조인 상태에서는 주먹 출발이 0.05초 늦다
- **오른쪽 스틱으로 가드 위치를 옮긴다.** 아래로 옮기면 팔꿈치로 바디를 막고, 옆으로 옮기면 그쪽 훅을 막는다
- 한쪽을 막으면 다른 쪽이 빈다

### 5.3 상체 움직임 (손 버튼과 LB가 없을 때 오른쪽 스틱)

| 방향 | 동작 | 효과 |
|---|---|---|
| 좌 / 우 | **슬립** | 머리가 옆으로 빠진다 (0.25초) |
| 아래 | **덕 / 롤** | 머리가 아래로 돌며 내려간다 (0.3초). 훅과 오버핸드를 피한다 |
| 뒤 (스틱을 몸 쪽으로) | **젖히기** | 머리가 뒤로 빠진다 (0.2초). 스트레이트를 피한다 |

- 상체 움직임은 스태미나를 조금 쓴다
- **슬립한 쪽 다리에 체중이 실린다.** 그 쪽 손의 다음 주먹은 준비 동작 없이 체중이 실린다
  - 왜: 슬립 앤 카운터가 규칙 없이도 자연스럽게 강해진다. 실제 선수가 하는 그대로다
- 너무 크게, 너무 자주 움직이면 균형이 흔들린다

## 6. 데미지

### 6.1 배율

| 조건 | 배율 | 판정 |
|---|---|---|
| **못 본 주먹** | **×2.0** | 타격 직전 0.25초 안에 방어자가 그 방향으로 반응하지 않았다(가드 이동, 가드 조이기, 상체 움직임, 뒤로 스텝). **방어자가 주먹을 치는 중이었어도 못 본 것으로 친다** |
| 카운터 | ×1.5 | 방어자가 공격자 쪽으로 움직이는 중이었다(스텝 또는 상체를 실어 치는 중). **"치는 중"이라는 이유만으로는 붙지 않는다.** 그건 '못 본 주먹'에서 이미 계산했다 |
| 체중 | ×1.0 ~ ×1.6 | 뒷손 트리거 깊이, 앞손은 스텝, 슬립 뒤 체중 |
| 가드에 막힘 | ×0.15 (조이면 ×0.05) | |

배율은 곱한다. 최대 ×4.0.

### 6.2 기본 타격력

| 기본형 | 타격력 | 성격 |
|---|---|---|
| 잽 | 4 | 누적, 거리 싸움 |
| 뒷손 스트레이트 | 8 | 누적, 균형 붕괴 |
| 훅 | 9 | **머리를 돌린다. KO 기여가 크다** |
| 어퍼 | 8 | 머리를 들어 올린다. 숙인 상대에게 ×1.3 |
| 오버핸드 | 10 | 머리를 돌린다. KO 기여가 크다 |

사이 궤도는 가까운 기본형 사이에서 보간한다. **회전 궤도(훅, 오버핸드)는 머리를 돌려서 KO를 만들고, 직선 궤도는 누적 데미지와 균형 붕괴를 만든다.**

### 6.3 머리

- 머리 데미지는 **누적**된다
- **턱 기준**: 시작값 36. 누적 데미지 10당 0.5씩 낮아진다(최저 8)
- 한 방의 최종 데미지가:

| 기준 대비 | 결과 |
|---|---|
| 75% 이상 | **흔들림** 3초: 다리가 풀려 이동 −40%, 가드가 처진다 |
| 100% 이상 | **다운** |
| 160% 이상 | **실신 KO** (즉시 경기 종료) |

- 예시: 못 본 체중 최대 뒷손 훅 = 9 × 1.6 × 2.0 × 회전 보너스 1.25 = 36 → 처음 상태에서도 다운. **완벽한 한 방은 첫 10초에도 상대를 눕힌다.** 실제 MMA가 그렇다
- 예시: 못 본 가벼운 훅 = 9 × 2.0 × 1.25 = 22.5 → 흔들림 직전. 체중이 조금이라도 실려야 흔들린다
- 예시: 보인 가벼운 잽 = 4 → 누적만 된다

### 6.4 몸

- LT로 낮춘 상태에서 친 주먹은 몸통으로 간다
- 몸 데미지는 **스태미나의 최대치를 깎는다**(데미지 1당 최대치 −1)
- **리버샷:** 상대의 오른쪽 옆구리(간)로 들어간 바디 훅, 즉 오서독스끼리면 **앞손 바디 훅**으로 최종 데미지 20 이상 → **0.5초 뒤에 무릎을 꿇는다**(다운)
  - 늦게 쓰러지는 것까지 현실과 같다. 치고 나서 한 박자 뒤에 쓰러지는 게 제일 짜릿하다

### 6.5 균형

- 맞으면 맞은 힘의 방향으로 균형이 밀린다
- 헛치면 앞으로 쏠린다([§4.7](#47-헛치면))
- **균형이 무너진 상태에서 흔들림 이상의 타격을 맞으면 다운이다**
- 균형은 게이지로 보여주지 않는다. **자세로 보인다.** 발이 벌어지고, 몸이 한쪽으로 기운다

## 7. 스태미나

| 행동 | 소모 |
|---|---|
| 주먹 | 3 ~ 8 (체중에 비례) |
| **헛친 주먹** | **×1.5** |
| 페인트 | 1 |
| 상체 움직임 | 2 |
| 스텝 | 거의 없음 |

- 최대 100. 주먹을 치지 않는 동안 초당 8 회복
- **25 이하면 지친다:** 주먹 속도 −20%, 타격력 −25%, 가드가 처진다, 숨이 거칠어진다
- 전부 몸으로 보인다. 숫자는 없다

---

## 8. 다운과 경기 종료

- **다운:** 쓰러진 선수는 2~4초 뒤 일어난다(머리 누적 데미지가 클수록 늦다). 그동안 상대는 자동으로 뒤로 물러난다. Phase 0에는 파운딩이 없다
- **다운 2번이면 TKO**
- **실신 KO는 즉시 종료**
- 3분이 지나면 **판정:** 머리 유효타 ×2 + 몸 유효타 합계가 많은 쪽이 이긴다. Phase 0 전용의 임시 규칙이다
- 경기가 끝나면 **아무 버튼이나 누르면 바로 다음 판**이 시작된다. 3초 이내

## 9. 몸이 상태를 보여주는 방법

HUD는 **라운드 시간**뿐이다. 나머지는 전부 선수 몸으로 보여준다.

| 상태 | 몸의 표현 |
|---|---|
| 준비 동작 (체중 싣기) | 어깨가 뒤로 빠지고, 뒷무릎이 굽고, 골반이 돈다. **상대가 읽을 수 있을 만큼 분명하게** |
| 맞음 | 머리가 맞은 힘의 방향으로, 힘의 크기만큼 꺾인다. 정해진 피격 모션이 아니다 |
| 흔들림 | 무릎이 풀리고, 스텝이 비틀거리고, 가드가 내려간다 |
| 균형 무너짐 | 발이 벌어지고 몸이 한쪽으로 기운다 |
| 지침 | 가드가 처지고, 어깨가 오르내리며 숨이 거칠다 |
| 몸 데미지 누적 | 맞을 때 몸이 접히고, 팔꿈치가 옆구리로 붙는다 |

**준비 동작의 가시성이 이 게임의 전부다.** 신호가 안 보이면 읽는 싸움이 아니라 운 싸움이 된다. 반대로 너무 크면 체중을 실은 주먹을 아무도 못 맞힌다. [§11](#11-실시간-조정-가능해야-하는-값)에서 가장 먼저 조정할 값이다.

---

## 10. 손맛

리얼 시뮬레이션이므로 이펙트로 손맛을 내지 않는다. 손맛은 이 네 가지에서 나온다.

1. **머리가 꺾이는 방향과 크기.** 가장 중요하다
2. **타격음.** 둔탁하고 무겁게. 막힌 소리, 맞은 소리, 제대로 들어간 소리가 확실히 다르다
3. **몸의 출렁임.** 피부, 땀이 튀는 것
4. **히트스톱.** 아주 짧게. 제대로 들어간 타격에만 0.03~0.05초. 템포를 죽이지 않을 만큼만

**KO 리플레이 (권장):** 다운이나 KO가 나오면 그 한 방을 2초 슬로모션으로 다시 보여준다. 못 본 주먹이었으면 화면에 짧게 **"못 봤다"**를 띄운다. 이 순간이 "야 방금 봤냐"를 만든다.

## 11. 실시간 조정 가능해야 하는 값

Phase 0는 이 값들을 돌리는 단계다. 방법은 개발 AI가 정한다.

- **준비 동작의 크기와 길이** (최우선)
- 주먹 속도 (기본형별), 커밋 지점
- 목표 추적량, 사거리 보정량
- 흐름 연결 보너스와 페널티
- 못 본 주먹 판정 창 (0.25초), 배율 전부
- 턱 기준, 흔들림/다운/KO 비율
- 스태미나 소모와 회복
- 헛침 쏠림 시간
- 히트스톱 길이

**디버그 표시 (켜고 끌 수 있게):** 양쪽 체력, 스태미나, 균형 수치, 주먹 궤도 선, 못 본 주먹 판정 결과.

---

## 12. 로그

테스트할 때 이 값들을 자동으로 기록한다.

- 주먹마다: 스틱 방향과 기울기, 체중, 가장 가까운 기본형, 맞음·막힘·헛침, 못 본 주먹 여부, 최종 데미지
- 페인트 횟수
- 흐름 연결 횟수
- 경기 결과와 경기 시간

**궤도 분포 로그가 특히 중요하다.** 플레이어가 스틱을 네 방향 끝으로만 쓰는지, 사이 궤도까지 쓰는지를 본다. 네 방향 끝만 쓰면 "궤도 무한"은 실제로 쓰이지 않은 것이다.

## 13. Kill Gate — 테스트 방법

### 대상과 진행

- **두 명씩 5쌍.** 격투기를 보는 사람과 안 보는 사람을 섞는다
- 알려주는 건 **조작표 한 장**뿐이다(페인트 방법 포함). 전략은 설명하지 않는다
- 구경꾼 3명을 따로 둔다

### 합격 기준

- [ ] 시키지 않았는데 **10판 이상** 붙는다: **5쌍 중 3쌍**
- [ ] "방금 봤냐", "뭐야", 탄성이 나온다: **5쌍 중 4쌍**
- [ ] 페인트를 스스로 쓴다: **경기당 평균 5회 이상**
- [ ] 사이 궤도(네 방향 끝이 아닌 궤도)가 전체 주먹의 **30% 이상**
- [ ] "마지막에 왜 쓰러졌어?"에 원인을 말한다("훅 오는 걸 못 봤어", "들어가다가 맞았어"): **10명 중 8명**
- [ ] 구경꾼이 "진짜 싸움 같다"고 한다: **3명 중 2명**

### 불합격이면 이 순서로 조정한다

1. **준비 동작 가시성.** 읽을 수 없으면 운 싸움이다
2. **주먹 속도와 입력 반응.** 템포가 느리면 UFC 5가 된다
3. **머리 꺾임과 타격음.** 손맛이 없으면 아무것도 소용없다
4. **배율과 턱 기준.** 한 방이 너무 쉽거나 너무 어렵다

**킥이나 태클을 넣는 건 조정 수단이 아니다.** 주먹 싸움이 재미없으면 다른 걸 붙여도 재미없다.

## 15. 테스트로 답할 열린 질문

기획 단계에서 정하지 않는다. 플레이테스트 데이터를 보고 정한다.

- 톡 치는 페인트가 빠른 잽과 헷갈리는가? 페인트를 다른 입력으로 떼어야 하는가?
- 목표 자동 조준의 양이 적절한가? 너무 많으면 실력 차이가 안 나고, 너무 적으면 첫 30초가 재미없다
- 오른쪽 스틱에 역할 세 개를 준 게 너무 복잡한가?
- 한 방 KO가 너무 자주 나오는가? 3분 동안 한 번도 안 나오는가?
- 0.16초 잽이 너무 빨라서 거리 싸움이 불가능해지는가?

## 16. 구현하면서 바뀐 것

봇 대 봇 시뮬레이션(`npm test`)을 돌려서 숫자를 맞추는 과정에서 바뀐 것들이다. 전부 디버그 패널에서 다시 조정할 수 있다.

| 항목 | 처음 | 지금 | 이유 |
|---|---|---|---|
| 페인트 입력 | 커밋 전에 버튼 떼기 | X + 손 버튼 | 잽의 커밋 지점(0.056초)보다 빨리 버튼을 뗄 수 없다 |
| 준비 없이 얻는 체중 | 제한 없음 (슬립하면 100%) | 최대 60% | 슬립, 흐름, 스텝이 겹치면 준비 동작 없이 풀파워가 나와서 읽을 수가 없었다 |
| 슬립한 쪽 손 체중 | 100% | 60% | 위와 같음 |
| 흐름 체중 보너스 | +0.3 | +0.2 | 위와 같음 |
| 카운터 조건 | 들어오는 중 **또는 치는 중** | 들어오는 중만 | 서로 치는 교환에서 매번 ×3(못 봄 ×2 × 카운터 ×1.5)이 붙었다 |
| 턱 기준 | 20 | 36 | 봇끼리 평균 7초 만에 경기가 끝났다 |
| 누적 데미지에 따른 턱 약화 | 10당 1 | 10당 0.5 | 여섯 방만 맞아도 턱이 무너졌다 |
| 흔들림 비율 | 60% | 75% | 못 본 가벼운 훅마다 흔들렸다 |
| KO 비율 | 180% | 160% | 턱 기준을 올린 만큼 조정 |
| 리버샷 기준 | 12 | 20 | 가벼운 바디 훅에도 나왔다 |
| 팔 길이 | 0.66m | 0.70m + 칠 때 상체 싣기 | 한 판에 341번 던져서 4번 맞았다. 닿지 않았다 |
| 균형 무너짐 판정 | 이번 타격이 민 뒤에 검사 | 민 전에 검사 | 스트레이트 한 방이 균형을 무너뜨리면서 동시에 다운시켰다 (버그) |

**봇 대 봇 기준값 (30판, `npm test`):** 평균 경기 시간 약 80초, 적중률 약 35%, 판당 흔들림 약 6회, 다운 약 2회. 봇은 방어가 무작위라 사람보다 훨씬 많이 맞는다. **최종 밸런스는 사람끼리 붙여서 정한다.**
